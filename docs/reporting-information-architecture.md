# Reporting Information Architecture

Status: aggregate demonstration structure only; no report data is persisted.

## Useful future levels

- Class overview: aggregate activity and session history.
- Activity completion: whether a teacher-led activity ran.
- Lesson performance: vocabulary response patterns by lesson.
- Vocabulary strengths: terms consistently recalled by teams.
- Needs review: terms a teacher may choose to revisit.
- Session history: teacher-owned aggregate records and recovery context.

The prototype table demonstrates lesson, session count, team count, aggregate
correct percentage, and a neutral review category. Fixture values are labeled
demonstration data and must never be described as real classroom outcomes.

## Claims deliberately excluded

There is no individual student tracking, mastery classification, ranking,
predictive analytics, automated educational judgment, or standards alignment.
Adding any of those requires evidence, curriculum validation, privacy review,
explainability, retention/deletion policy, accessibility review, and explicit
owner approval.

## Accessibility

Wide viewports use a semantic table with caption and column headers. Narrow
viewports preserve the same source order while CSS presents row labels for a
readable card-like layout. Status and meaning are textual and do not rely on
color.
