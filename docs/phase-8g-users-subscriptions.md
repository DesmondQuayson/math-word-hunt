# Phase 8G users and subscriptions

Phase 8G gives the sole MFA-verified owner a minimized consumer-account view and bounded operations. It is not a raw Auth, Stripe, billing, or entitlement editor. The view includes account ID and email, confirmation and account status, safe timestamps, trial/subscription/entitlement summaries, consent versions, deletion state, immutable support notes, refund-review state, and relevant audit actions. Passwords and hashes, MFA material, tokens, full IP history, card/payment details, provider secrets, and raw webhook payloads are never selected or rendered.

Every operation uses same-origin CSRF validation, a short server-owned admin session, a unique idempotency key, and immutable prepared/completed evidence. Suspension, restoration, Auth-session revocation, complimentary grants/removal, refund denial, and emergency revocation additionally require an AAL2 session started within the last five minutes and a bounded reason. These requirements are rechecked by `SECURITY DEFINER` database functions; browser values cannot grant authority. Support notes are append-only and warn against secrets, payment data, and student information.

Implemented workflows are resend confirmation through configured Auth delivery, global Auth-session revocation, application suspension/restoration, validated Customer Portal opening, cancellation-at-period-end through that portal, eligible first-charge refund-review submission, reviewed denial, one active complimentary grant of 1–90 days, grant removal, and emergency access revocation. Provider calls receive an audit preparation record before the call and a success/failure/manual-review result afterward. Portal URLs are short-lived and never stored. Suspension and complimentary access do not edit Stripe projections or authoritative billing rows.

Refund approval remains read-only because the current provider contract cannot yet prove and idempotently refund the exact eligible payment. Permanent deletion remains read-only because cancellation, required retention, legal hold, identity deletion, and rollback checkpoints are not fully approved. A deletion-pending account cannot be restored or overwritten by Phase 8G. These controls must stay disabled until their complete safe workflows exist.

The complimentary entitlement table is private and independent of Stripe. An authenticated consumer may call only the zero-argument own-entitlement resolver, which derives identity from `auth.uid()` and returns a current expiry only for an active account. All cross-account table access and all admin mutation functions are denied to browser roles.

Rollback uses `supabase/rollback/phase8g_users_subscriptions.sql` after first disabling the Phase 8G admin surface. Preserve audit evidence under the applicable retention decision before rollback. Never roll back by modifying Stripe subscription records or deleting customer evidence.
