## Primary change

The main MathNexa header now carries the approved bunny/ring brand identity, with
**"Math" in white and "Nexa" in `#FF4F9A`**. No layout change.

The header previously carried an inline SVG glyph on a yellow tile with an offset coral
shadow, beside "Math" white and "Nexa" in the yellow brand secondary. Worth recording for
whoever looks next: this was **not** an image asset, a public file, or App Router metadata —
it was hard-coded markup in `components/site-header.tsx` styled by `.brand-mark` and
`.brand-name` in `styles/components.css`.

The mark is generated by `scripts/generate-brand-mark.mjs` from the **same** artwork the app
icons come from (`apps/platform-web/assets/brand/mathnexa-app-icon-source.jpg`), so the
header, the browser tab and the marketing banner are one identity and none of them is a
redraw. The full lock-up — bunny, inner wordmark, four sub-icons — is unreadable at the 48 px
the header renders, so the mark is the part that survives: the bunny inside its own teal
ring, cropped from the approved image. Output is
`apps/platform-web/public/brand/mathnexa-mark.png`, 144 px for a 48 px slot, deterministic
(`b8cafb9705c88709b451a0792a0760eb2976dd60ce992030d9d3cce6a6ac4ba9`).

The wordmark stays **live text** rather than becoming a raster: text is crisp at every zoom
level and device pixel ratio, it reflows, and it still reads if the mark has not loaded. A
baked-in wordmark would fail all three.

## Two deliberate choices

**The pink is `--color-accent-pink` (#ff4f9a), not the artwork's `#f02870`.** At 17px/800 this
wordmark sits just *under* WCAG's large-text threshold, so it needs 4.5:1 against the header
navy `#082c43`. The artwork pink reaches only **3.61:1** and would miss the AA target
`docs/accessibility-visual-standard.md` commits the shell to; the established token is the
same brand pink a shade brighter at **4.71:1**. In the 636×180 marketing banner the artwork
pink is correct, because the wordmark there is 45 px. The rule is scoped to `.site-header`
because **`.brand-name` is shared with the site footer**, whose `strong` is turquoise and is
not part of this change.

**The mark is a plain `<img>`, not `next/image`.** A fixed 48 px mark is already delivered at
its final size (12 KB, 3× for density), so an optimisation round trip would buy nothing.
Intrinsic `width`/`height` are set, so the header reserves the space and the navigation
cannot shift while it loads. It stays `aria-hidden` with empty `alt` because the link already
carries "MathNexa home" — alt text would make a screen reader announce the brand twice.

## Verification at freeze

**Production identity.** `kv9vnqu2t` is the newest deployment on the project, ● Ready, and
both `mathnexa.com` and `www.mathnexa.com` resolve to it. Of the 12 build assets the live
home page references, 9 exist under the same name in a local build of `201e7d4` and **all 9
are byte-identical**; the remaining 3 are the Turbopack runtime and two env-dependent chunks
that Vercel builds with production configuration a local build does not have.
`/brand/mathnexa-mark.png` returns 200 and sha256-matches the committed asset.

Home, Games, Account and Sign in alike. `Math` `rgb(255,255,255)`, `Nexa` `rgb(255,79,154)`,

no page overflow.

**Engines.** The mark decodes and renders at 48×48 from its 144×144 source in Chromium
desktop, Chromium mobile, WebKit desktop and WebKit mobile. In all four the brand link's
accessible name is "MathNexa home", announced once, with the mark `aria-hidden` and `alt=""`.

**v1.2.2 features intact.** `favicon.ico`, `icon.png`, `icon1.png` and `apple-icon.png` all
still sha256-identical to the committed assets. Sign-in still defaults to `/`; `/games`,

(`https://attacker.example`, `//attacker.example`, `javascript:`, `%252Fgames`,

most one hop: Home, Sign in, Sign up, About, Help and Accessibility direct; Games, MAP Prep,

**Gates.** typecheck 0 · lint 0 errors (8 pre-existing warnings) · unit 291 passed / 293 ·
production build green · `npm audit --omit=dev` 0 vulnerabilities.
